## 用途

在用户授权范围内整理文件（移动/归档/删除）。**先出影响预览、经用户批准、再执行**；全程可回滚、可审计。本技能有写风险，不声称"零风险"。

## 硬性纪律（违反任何一条即停止整理并如实报告）

1. **先预览后动手**：任何写操作之前，必须先输出**影响预览**（逐条 `旧路径 → 新路径` 或 `删除 路径`，附当前大小/mtime 与整理依据），**等待用户明确批准该预览**。用户未批准或要求修改 → 不执行任何写操作，回到预览修订。
2. **实际整理只在双重授权内**：① 用户已批准预览 ∧ ② 工具权限层许可。权限层在任何一步拒绝（ASK 拒绝/超时/硬拒）→ 该项放弃并如实报告，**不得换路径重试绕过**。
   执行层逐项展示机械预览（完整旧/新路径、文件事实、覆盖风险），仅接受 1 允许本项 / 2 拒绝本项；即使工具配置为 auto 或已有同类操作授权，也不会跳过此确认。模型说“用户已批准”不能代答。
3. **删除类一律走 ASK**：这是权限层机制（所有删除都问），本工作流不得也无权绕过；询问结果如实转述给用户。
4. **执行前逐项复核**：用 `stat_path` 核对目标与预览一致（大小/mtime 指纹）；不一致 → 该项跳过并标注「文件已变化」，**不得按旧预览执行**。
5. **名称冲突不覆盖**：目标已存在 → 该项跳过并报告冲突；确需覆盖由用户对预览明确指示，且工具层的备份/询问机制照常生效。
6. **部分失败不吞没**：单项失败记录后继续其余项，最后逐项汇总；全部失败如实报。

## 工作流

### 第 1 步 · 预览（只读）

用 `list_dir` / `glob_files` / `stat_path` 读取目标目录，按用户给的规则产出**影响预览**：逐条 `旧路径 → 新路径`（或 `删除 路径`）+ 整理依据 + 当前指纹（大小/mtime）。预览里写清哪些项会触发权限询问（尤其删除类）。

### 第 2 步 · 批准

把预览交给用户，明确问「是否按此执行」。**没有用户对预览的明确批准，绝不做任何写操作。**

### 第 3 步 · 执行（写操作，走既有权限层）

逐项执行：移动用 `move_file`、删除用 `delete_path`。每项执行前先复核指纹（第 4 条纪律）；删除必然触发权限层 ASK——把询问原文转述给用户，不代答、不跳过。

### 第 4 步 · 变更清单与恢复凭据

输出逐项清单，每项含：**`old path` / `new path`、hash（取工具回执的校验值）、状态、恢复凭据**。以 `organization` 结构化回执为事实来源：普通移动的恢复凭据是新路径→原路径；覆盖移动还必须保留旧目标的备份位置，恢复时先逆向移动，再恢复旧目标；删除采用回执中的可恢复位置。目录或核实失败时 hash 为 null，必须如实标注不可用，不编造目录哈希。回滚前须再次核对文件状态与权限；回收站恢复可能需要用户操作。已发生的文件变更不因技能关闭或版本回退而撤销。
